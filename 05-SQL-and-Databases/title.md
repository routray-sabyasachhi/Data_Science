# SQL and Databases

## Why study this
Much organizational data lives in databases. SQL lets you retrieve, combine, validate, and summarize it close to its source, while database concepts help you avoid incorrect joins and inconsistent records.

## Topics and subtopics
- Relational model: tables, rows, columns, keys, constraints, schemas, relationships, normalization and denormalization
- SQL basics: `SELECT`, aliases, `WHERE`, `ORDER BY`, `LIMIT`, distinct values, NULL semantics
- Aggregation: `COUNT`, `SUM`, `AVG`, grouping, `HAVING`, conditional aggregation
- Joins: inner/left/right/full/cross, self joins, many-to-many joins, duplicate row traps, join keys
- Subqueries and CTEs: scalar, correlated, recursive awareness, readability
- Set operations: `UNION`, `INTERSECT`, `EXCEPT`
- Advanced querying: window functions, partitions, frames, ranking, lag/lead, running totals
- Data definition and modification: create/alter/drop, insert/update/delete, upsert
- Data types: numeric, text, dates/timestamps, Boolean, JSON awareness; casting and precision
- Database correctness: primary/foreign keys, unique/check/not-null constraints, transactions, ACID
- Performance: indexes, query plans, selectivity, avoid unnecessary scans, basic tuning
- Modeling: ER diagrams, star/snowflake schemas, facts/dimensions, slowly changing dimensions awareness
- Access: clients, Python connectors, parameterized queries, credentials, least privilege
- Dialects and practical differences: PostgreSQL baseline, portability considerations
