# Projects and Portfolio

## Why study this
Projects turn separate skills into evidence that you can answer useful questions from raw inputs through a reproducible result. A strong portfolio shows judgment, not just code or model scores.

## Topics and subtopics
- Project selection: meaningful question, accessible lawful data, scope, audience, success measure
- Proposal: problem statement, stakeholder, assumptions, risks, milestones
- Data sourcing: provenance, licensing, collection method, privacy, schema, limitations
- Reproducible repository: README, environment/dependencies, data instructions, notebooks/scripts, source citations
- Analysis: data validation, cleaning log, EDA, baseline, method selection, evaluation, error analysis
- Modeling: leakage checks, suitable split, metrics aligned to decision, uncertainty, fairness checks where relevant
- Deliverable: concise report, visualizations/dashboard, recommendation, reproducible code
- Quality: modularity, tests, documentation, version control, deterministic rerun
- Limitations: data gaps, assumptions, representativeness, causality, generalization, maintenance needs
- Portfolio presentation: concise case study, screenshots/results, explain choices, answer critique
- Suggested projects: exploratory report, SQL business analysis, experiment analysis, forecasting, supervised ML, text/image specialization, deployed batch or API system
